NSBENCH.TTP - EWeb's measuring tool
===================================

What it does
------------
NSBENCH reads a web page saved as a file and runs on it the parts of
NetSurf that EWeb starts from: the HTML parser (Hubbub) and the CSS
engine (LibCSS), and EWeb's own CSS engine, which is meant to replace
LibCSS. It times each part on your Atari, so we can see how a real
Falcon compares with the emulators EWeb's design was measured on. It
doesn't show the page itself.

What it needs
-------------
Any Atari Falcon (no FPU needed), with plain TOS, MagiC or MiNT. With
TT-RAM (an accelerator such as the DFB1) it loads and works there. A big
page wants a few megabytes of free memory.

How to use it
-------------
1. Copy NSBENCH.TTP to a folder on your hard disk, with the pages that
   come with it:
     SAMPLE.HTM   a small page (1 KB)
     NEWS.HTM     a made-up news front page with a Hebrew section, built
                  to cost what the web's median page does (72 KB, 816
                  elements)
     NEWS.CSS     its stylesheet (83 KB), like a news site's
   To test a real page too, save it on another computer ("Save page as",
   HTML only) and copy it over with a short name, such as BBC.HTM; its
   stylesheet too if you have it (BBC.CSS).
2. Double-click NSBENCH.TTP and type the file names in the box:
       -E both NEWS.HTM NEWS.CSS
   (both CSS engines, one after the other), or
       NEWS.HTM NEWS.CSS
   or
       SAMPLE.HTM
   or
       BBC.HTM BBC.CSS
3. It prints what it found and how long each part took, then waits for
   a key. The same lines go into NSBENCH.LOG, in the same folder.

Options (type them before the file names)
-----------------------------------------
   -E both   time both CSS engines: LibCSS, then EWeb's own; -E ewcss
             EWeb's alone; -E libcss (the default) LibCSS alone
   -r 5      run it five times and show the average (good for small
             pages such as SAMPLE.HTM: the timer counts in steps of 5 ms;
             NEWS.HTM takes long enough once)
   -P 1      the HTML only; -P 2 adds the stylesheets; -P 3 (the
             default) also gives every element its style
   -c 1460   feed the parser in pieces of this many bytes, as from the
             network (the default is 4096)

What the first lines say about your Atari
-----------------------------------------
   machine   the machine (_MCH), the CPU and whether there is an FPU
   caches    the 68030's caches: both should be on
   loop      a short loop's speed: a 68030 at 50 MHz with its caches on
             manages about 6.2 to 8.3 million rounds a second
   program   whether NSBENCH runs in TT-RAM (an accelerator's, fast) or
             ST-RAM (the Falcon's own), and how much of each is free
   reading   how fast each kind of RAM reads, in KB a second
   heap      (at the end) where NSBENCH's memory for the page came from

What the numbers mean
---------------------
   html      parsing the page into a tree of elements
   css       parsing the stylesheets: a small built-in one, the files
             you name and the page's own <style> blocks
   select    working out every element's style
The times are in milliseconds. "time per run" is LibCSS's; "time per
run, EWeb's CSS" is EWeb's own engine's, on the same page and sheets.
The "EWeb's CSS" lines before them say what it did: how many rules,
how many of their declarations it had to read, and how many elements
took a style from a sibling ("shared") or one already worked out
("cached") instead of working it out again.

Please send NSBENCH.LOG back, with your Atari's details (for example as
an issue on github.com/whomper/EWeb): it shows how a real DFB1 compares.
